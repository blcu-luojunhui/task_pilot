# 产品需求文档（PRD）—— Yggdrasil 认知架构

文档版本    3.0
状态    草案（带思想溯源）
日期    2026-07-21
关联系统    Agent 框架现有模块：skill_registry、agent_memory、reflection

## 1. 背景与问题

### 1.1 现状痛点

当前 LLM Agent 系统的三大核心资产——技能（Skill）、记忆（Memory）与知识（Knowledge）——在架构上相互隔离：

- **Skill**：以 `@skill` 注册或 Markdown 描述存在。它不知道自己依赖哪些知识、曾被哪些场景触发、产生过什么长期影响。

- **Memory**：以 reflection 记录存在，通过 `scope_key` 和 `trace_id` 关联。但与技能无显式联系——你无法查询"这个技能执行时，过去发生过什么"。

- **Knowledge**：以静态文档注册在 skill_registry 中。它不引用任何具体经验，也无法随着系统使用而自动演化。

运行时，Agent 只能依赖 LLM 从扁平的上下文窗口中"碰运气"连接这三者。这导致三个核心问题：

1. **经验无法沉淀**：每次 Run 产出的反思孤立地存在记忆表里，下一轮几乎不可能被精确召回。

2. **知识无法生长**：静态文档在写成那一刻就开始过时，没有任何机制让它们从实际执行结果中更新。

3. **技能与上下文断裂**：Skill 执行时不知道自己身处什么领域、有过什么历史、有哪些相关知识可用。

### 1.2 思想来源

这个问题的本质，在几个不同领域已经被反复触及：

- **认知科学中的记忆分类**：心理学将长期记忆分为**程序性记忆**（知道如何做，对应 Skill）和**陈述性记忆**（知道是什么，对应 Knowledge），而**情景记忆**（个人经历，对应 Memory）是两者的黏合剂。当前 Agent 恰恰缺少这种黏合。

- **复合 AI 系统 (Compound AI Systems)**：Berkeley 的研究指出，LLM 的真正能力来自"模型 + 检索 + 工具 + 记忆"的复合体。但业界目前只做到了组件拼凑，缺少一个统一这些组件的数据模型。

- **MemGPT / Letta**：最早提出"给 LLM 一个操作系统级的内存管理"，让模型能自主决定何时把上下文存入长期记忆、何时检索。但它解决的只是 Memory 层，没有涉及 Skill 和 Knowledge 的结构化。

- **认知架构 ACT-R**：在经典 AI 中，ACT-R 将知识明确分为陈述性模块和程序性模块，两个模块的交互产生认知行为。我们的 Agent 缺少的正是这种"模块间的结构化连接"。

- **Tree of Thoughts**：证明将 LLM 的推理过程展开为树状结构，能显著提升复杂问题求解能力。但这棵树是临时的推理树，每次用完即弃。我们需要的是一棵持久的知识树，能跨越无数次推理而不断生长。

把这些片段编织在一起，就自然引出一个构想：**一棵活的、能自我进化的认知拓扑——世界树（Yggdrasil）**。

## 2. 产品愿景

构建一棵持久、可生长的统一认知结构，将 Skill、Memory、Knowledge 三种资产组织为树上的有机节点。

树会随每一次 Agent Run 而生长：经验化为根，能力伸展为枝，知识茂盛为叶，运行结果最终回落为新的养分。它既能被精确检索，也能在隔离沙盒中安全推演，还能自动识别并隔离有害模式。

最终目标：让 Agent 从"每次重建上下文"走向"持续生长，越用越强"。

## 3. 核心概念

### 3.1 树的隐喻映射

| 树的部位 | 系统对应 | 说明 | 灵感来源 |
|---------|---------|------|---------|
| **根 (Root)** | Memory — 执行反思、跨 Run 的经验判断 | 高频记忆扎根更深，检索时优先浮现；按领域分层扎根 | 认知科学中"情景记忆"的巩固机制；MemGPT 的长期记忆自主管理 |
| **干 (Trunk)** | Agent 主循环 / 决策主干 | 不存为静态节点，而是运行时从根到某枝叶的"决策路径"，可被记录为轨迹记忆 | 复合 AI 系统的控制流概念 |
| **枝 (Branch)** | Skill — 可执行能力（API、代码、Prompt 模板） | 调用越频繁，枝越粗（权重提升）；从干上分叉，是系统作用于外部世界的接口 | ACT-R 的"程序性记忆"；Semantic Kernel 的技能文件夹组织 |
| **叶 (Leaf)** | Knowledge — 领域知识、模式、最佳实践 | 附着于枝，为执行提供静态上下文；可随时间被 Memory 的总结所更新 | RAG 与 GraphRAG 的知识检索思想 |
| **果 (Fruit)** | 执行结果 / 产出 | Skill 调用的结果；被反思加工后形成新的 Memory（落叶归根）或强化已有 Knowledge | 斯坦福小镇（Generative Agents）的记忆流与反思机制 |

五个元素构成一个闭环：

**Skill 调用 → 产生结果 (Fruit) → 反思形成 Memory (Root) → 提炼为 Knowledge (Leaf) → 被后续 Skill 检索使用**

### 3.2 三层连接边

节点之间通过三种方式关联，各司其职：

1. **显式边（结构关系）**：如 Skill 声明依赖哪些 Knowledge，Knowledge 引用哪些 Memory。可解释、可审计。

2. **隐式边（语义关联）**：基于 embedding 向量距离计算。灵活、可发现未知关联。

3. **共现边（统计关联）**：运行时记录"Skill A 执行时 80% 伴随 Knowledge B"。用于自动推荐加边、修剪权重。

## 4. 功能需求

### FR-1 统一节点模型

所有实体在存储层抽象为 `tree_node`：

属性：`id`, `type`(skill\|knowledge\|memory), `parent_id`, `content`, `embedding`, `metadata`, `weight`, `health`, `created_at`, `updated_at`。

- **显式关系**：通过 `node_links` 表维护多对多关系，作为树枝间的结构化连接。
- **图约束**：整个图必须保证无环（DAG），新增显式边时执行可达性检测。
- **隐式关系**：所有节点维护向量索引，支持基于语义距离的模糊发现。

设计要点：三种边共存于同一张图中，显式边是 Agent 确定性依赖的依据，隐式边和共现边是发现和演化的依据。

### FR-2 领域驱动的层次骨架

根节点为 `/`，第一层按领域划分（如 `database/`，`http/`，`auth/`）。

每个领域内部预设 `skills/`，`knowledge/`，`memories/` 三个子空间。

当某领域节点数超过阈值时，系统自动建议拆分子领域，树深度自然生长。

支持粗粒度查询（"给我数据库相关的全部能力"）和细粒度导航（"MySQL 下所有事务相关的记忆"）。

设计考量：初始骨架是静态的、可预测的，保证冷启动可靠。树的深度扩展是动态的、数据驱动的。

### FR-3 动态生长与权重系统

- **自动挂载**：每次 Agent Run 后，产生的 Memory 自动挂载到执行时所在的分支下。

- **权重更新规则**：
  - Skill 成功调用 +1；产出正向结果 +2
  - Knowledge 被检索并采纳 +1
  - 关联边权重随共现频率累积

- **时间衰减**：长期未访问的节点权重按指数衰减（但不删除），检索时自然沉底。

- **生长推荐**：当共现边强度超过阈值，系统自动建议建立显式边。

灵感：人类记忆的间隔重复和遗忘曲线——常用则强，不用则弱，但不消失。

### FR-4 上下文子树检索

核心 API：`retrieve_subtree(intent_embedding, max_tokens, max_depth)`

工作流：

1. 接收当前任务意图的向量表示。
2. 在全树中检索最相关的领域锚点节点。
3. 以锚点为根，向下收集子树（技能、知识、相关记忆）。
4. 按 `weight × semantic_relevance` 综合排序剪枝，确保总内容量不超过 LLM 上下文窗口的配置上限。
5. 返回结构化子树摘要，注入 LLM 提示。

设计考量：这本质上是把原来扁平的全量上下文，替换为与当前意图拓扑相关的结构上下文。既降低了 token 消耗，也提高了信息精度。

### FR-5 沙盒分支

在执行高风险或探索性任务前，可创建主树的读写快照作为独立分支。

沙盒中的所有写操作完全隔离，不影响主干。

沙盒结束后，由评估器（LLM 评判 + 结果规则）判定：

- **良性**：自动合并到主树，高质量记忆提升权重。
- **有害**：分支标记隔离，移至受限区保存，供后续分析。

支持并行多沙盒，用于对比不同策略的产出。

灵感：Tree of Thoughts 的多路径探索 + 软件工程的 sandbox 模式。让 Agent 能"安全地犯错并从错误中学习"，而不污染生产系统。

### FR-6 有害模式隔离与自动回滚

- **节点健康值**：每个节点有 `health`（0-1），默认 1.0。被标记为有害源后降为 0。
- **传染衰减**：与有害节点有强关联的节点，健康值按预设衰减因子递减。
- **检索屏蔽**：健康值低于阈值的节点在检索时自动过滤；关联 Skill 调用时弹出风险警告。

**自动回滚**：

1. 当某子树有害节点比例超过阈值，系统自动定位该子树最近的健康快照。
2. 创建新主干分支，将健康版本设为当前活跃态。
3. 所有依赖该子树的 Agent 会话收到刷新信号。
4. 被替换的子树保留完整操作日志，不可修改但可审计。

灵感：分布式系统的"熔断"机制 + 事件溯源（Event Sourcing）的回滚思想。系统的核心假设是：错误会传播，而且必须能被整体撤销。

### FR-7 树健康巡检服务

一组后台异步任务，周期性遍历树节点。

巡检项：

- 健康值是否低于阈值
- 访问频率是否显著下降（可能枯萎）
- 节点内容是否与其他节点高度相似（冗余）
- 引用完整性（是否有悬空边）

自动操作：标记冗余、建议合并、清理无效边。

警报：技能长期无成功执行、知识长期未更新、分支整体活跃度过低。

设计考量：生长必须有修剪，否则树会退化为无序灌木丛。巡检服务是树的"代谢系统"。

### FR-8 版本历史与不可变日志

树采用版本化策略：每次沙盒合并、自动回滚或人工编辑均产生新版本（commit）。

维护 append-only 操作日志，记录所有结构变更（增、删、改、移动），含时间戳、操作者、变更前后快照引用。

支持时间点恢复和任意历史版本状态查看。

灵感：Git 的数据模型 + Event Sourcing。系统不能只知"当前状态"，必须知"如何变成这样"。

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 子树检索 P95 < 200ms，依赖向量索引 |
| 规模 | 单棵树支持 10^5+ 节点，按租户分片 |
| 一致性 | 沙盒合并采用 Compare-and-Swap 乐观锁，冲突时人工裁决 |
| 可观测性 | 树状可视化：权重热力图、生长动画、健康度面板 |
| 安全 | 节点可设访问标签；隔离区仅限授权角色；操作日志防篡改签名 |

## 6. 用户故事

| 角色 | 故事 |
|------|------|
| AI 产品工程师 | 我想把现有的 skill_registry 和 agent_memory 一键导入世界树，形成统一资产，告别三套不互通的数据。 |
| LLM Agent | 当我接到任务时，我可以通过一次检索拿到与该任务拓扑相关的技能、知识和历史经验——而不是被全量上下文淹没。 |
| 系统管理员 | 我可以让 Agent 在隔离沙盒中尝试高风险操作，确认无害后再合并回生产主干。 |
| 运维人员 | 当一段错误知识导致多次任务失败，系统能自动将其标记并隔离，通知我去分析，而不是任其扩散。 |
| 开发者 | 我能像查看 Git 日志一样追溯世界树的历史，理解任何一个决策路径的来龙去脉。 |

## 8. 实施路线

### Phase 1：静态基础树（MVP）
- 实现统一节点模型与领域分层
- 迁移现有 Skill、Memory、Knowledge 到 `tree_node`
- 实现基础子树检索，替代手动拼接提示

**交付**：Agent 基于结构化的树上下文执行任务，首次实现三者的拓扑耦合

### Phase 2：动态生长与沙盒
- 运行时自动挂载 Memory 节点，权重动态更新
- 沙盒分支机制：fork → 执行 → 评估 → 合并/隔离
- 人工标记有害节点与手动隔离

**交付**：Agent 能从经验中学习，并安全探索未知

### Phase 3：自动免疫与健康巡检
- 有害模式自动检测与健康衰减模型上线
- 自动回滚协议
- 巡检服务持续运行

**交付**：系统具备自愈能力，能自动抵御多数有害循环

### Phase 4：多智能体与高级特性
- 多 Agent 子树共享与权限隔离
- 可选：节点资产化、可对话知识节点

**交付**：多智能体协作的认知生态

## 9. 风险与待解决问题

| 风险 | 说明 | 缓解策略 |
|------|------|----------|
| 上下文长度溢出 | 子树检索结果可能仍超过 token 限制 | 严格配置 `max_tokens`，引入层级摘要（子树上卷为摘要节点） |
| 有害判定误报 | 自动判定可能将正常知识误标记为有害 | 初期以规则为主（如失败率），人工审核为辅；后期引入专门分类器 |
| 沙盒合并冲突 | 多沙盒并行时可能修改同一节点 | 领域级锁 + Compare-and-Swap 乐观并发控制 |
| 冷启动 | 初始树缺少足够节点和边 | 回放历史 Run 日志自动建节点；支持人工标注种子数据 |
| 向量漂移 | Embedding 模型升级后旧向量不再准确 | 版本化 embedding 模型引用，支持后台异步重建索引 |
| 环路风险 | 不当的显式边可能形成环路 | 每次加边执行 DAG 可达性检测，拒绝会成环的操作 |

## 10. 核心设计哲学

1. **结构优于规模**：一棵组织良好的小树，胜过一片混乱的森林。优先保证节点之间的关系质量，而非追求数量。

2. **生长需要修剪**：必须有一组反向力量（时间衰减、健康巡检、有害隔离）与生长对抗，否则系统会膨胀为无用的噪音集合。

3. **可回滚比正确更重要**：在动态演化系统中，错误不可避免。真正的可靠性不来自"永远正确"，而来自"能快速发现并回滚错误"。

4. **三层连接各司其职**：显式边保证可解释性，隐式边保证灵活性，共现边驱动自动演化。三者缺一不可。

5. **Agent 与环境共同进化**：世界树不是静态的知识库，而是 Agent 与环境交互的沉淀物。树的形态最终反映的是系统的使用历史。
